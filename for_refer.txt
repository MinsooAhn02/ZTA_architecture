1. Hyperion이 해결하려는 문제 (논문 핵심)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  마이크로서비스 환경에서 컨테이너 간 통신은 소프트웨어 기반 네트워크 데이터 플레인
  (네트워크 가상화 + 접근 제어 정책 평가)을 거치는데, 이 과정에서 상당한 CPU 오버헤드와
  레이턴시 증가가 발생한다.

  Hyperion은 SmartNIC(스마트 네트워크 인터페이스 카드) 하드웨어에 이 데이터 플레인을
  통째로 오프로드하여 호스트 CPU 부담 없이 고성능·고보안 컨테이너 네트워킹을 실현한다.

  측정 결과 (소프트웨어 기반 대비):
    - HTTP 레이턴시  : 최대 2.25x 개선
    - 처리량(throughput): 최대 4.3x 개선
    - CPU 사용량     : 최대 4x 감소

2. 본 연구 (ZTA 프로젝트) 개요
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  NIST SP 800-207 기반 Zero Trust Architecture(ZTA)를 Kubernetes 환경에서
  소프트웨어 스택으로 구현한 연구이다.

  사용 기술:
    - Istio Service Mesh : 서비스 간 mTLS 강제, SPIFFE/SVID 기반 워크로드 인증,
                           JWT 서명 검증(JWKS), AuthorizationPolicy 적용
    - OPA (Open Policy Agent): Rego 정책으로 역할(role) + 경로(path) + 메서드(method)
                                + 디바이스 상태(device posture) 컨텍스트 기반 인가
    - Keycloak : OAuth2/OIDC 기반 JWT 발급, Realm/Role 관리

  검증한 보안 시나리오 (A~E):
    A. North-South 차단 + 내부 Lateral Movement 방어 (mTLS STRICT + SPIFFE allowlist)
    B. JWT 위조/변조 탐지 (Istio JWKS 서명 검증)
    C. 컨텍스트 기반 접근 제어 (role + method + path 조합 OPA 정책)
    D. JWT Claim 기반 Role 인가 (Keycloak 서명 토큰에서 직접 역할 추출)
    E. Device Posture 게이트 (디바이스 상태 헤더 검증 → 비정상 디바이스 차단)

3. 두 연구의 연결점 (공통 문제의식)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  ┌─────────────────────────────────────────────────────────────────────────┐
  │  두 연구 모두 "컨테이너/마이크로서비스 환경에서 보안 정책 집행(enforcement)의  │
  │  위치와 방식을 어떻게 설계할 것인가"라는 동일한 문제를 다룬다.               │
  └─────────────────────────────────────────────────────────────────────────┘

  공통점:
    1) 접근 제어 정책을 애플리케이션 코드 밖 (인프라 레이어)에서 집행한다.
       - Hyperion : SmartNIC 하드웨어 데이터 플레인에서 처리
       - 본 연구   : Istio Envoy 사이드카 + OPA 정책 엔진에서 처리

    2) 마이크로서비스 간 East-West 트래픽의 보안을 명시적으로 다룬다.
       - Hyperion : 컨테이너 간 패킷 수준 접근 제어
       - 본 연구   : mTLS STRICT + SPIFFE 기반 서비스 아이덴티티 검증

    3) 기존 컨테이너 워크로드를 수정하지 않고 보안 기능을 투명하게 삽입한다.
       - Hyperion : 애플리케이션 수정 없이 SmartNIC에서 투명하게 오프로드
       - 본 연구   : Istio 자동 사이드카 인젝션으로 앱 코드 변경 없이 정책 적용

4. 차별점 / 각 연구의 기여
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Hyperion의 기여:
    - 보안 정책 집행을 하드웨어(SmartNIC)로 내려서 성능 오버헤드 문제를 해결
    - 관심 대상: 패킷 레벨 네트워크 가상화 + 단순 접근 제어 규칙의 하드웨어 구현
    - Zero Trust의 "지속적 검증(continuous verification)" 원칙보다는
      "성능 최적화"에 초점

  본 연구(ZTA)의 기여:
    - NIST SP 800-207의 Zero Trust 원칙(명시적 검증, 최소 권한, 침해 가정)을
      실제 Kubernetes 클러스터에서 End-to-End로 구현하고 검증
    - 단순 패킷 필터링을 넘어 JWT 클레임·디바이스 상태·HTTP 컨텍스트 등
      고수준(L7) 속성을 정책 판단에 결합
    - 소프트웨어 기반이기 때문에 정책을 코드(Rego)로 표현하고 동적으로 변경 가능
    - 관심 대상: "누가, 어떤 맥락에서, 무엇에 접근하는가"라는 ZTA 철학의 구현

  [한국어 버전]
  ─────────────────────────────────────────────────────────────────────────
  저는 NIST SP 800-207 기반 Zero Trust Architecture(ZTA)를 Kubernetes 환경에서
  소프트웨어 스택(Istio + OPA + Keycloak)으로 구현하고, 총 18개 보안 시나리오(JWT
  위조/변조, Lateral Movement, 컨텍스트 기반 인가, 디바이스 상태 게이트 등)를
  실험적으로 검증하는 연구를 진행했습니다.

  이 과정에서 IEEE TCC 2024에 게재된 Hyperion 논문을 접하게 되었습니다. Hyperion은
  SmartNIC 하드웨어에 컨테이너 네트워크 데이터 플레인(네트워크 가상화 + 접근 제어)을
  오프로드하여 소프트웨어 기반 대비 최대 4.3배 처리량 개선과 4배 CPU 절감을 달성합니다.

  두 연구는 "컨테이너 환경의 보안 정책 집행을 애플리케이션 외부 인프라에서 투명하게
  처리한다"는 문제의식을 공유하지만, 접근 방식에서 뚜렷한 차이를 보입니다. Hyperion은
  성능 최적화를 위해 하드웨어 오프로드에 집중하는 반면, 저의 연구는 JWT 클레임·HTTP
  메서드·경로·디바이스 상태 같은 고수준(L7) 컨텍스트를 조합한 동적 정책 판단,
  즉 ZTA의 "지속적·맥락적 검증" 철학을 소프트웨어로 구현하는 데 초점을 둡니다.

  앞으로는 이 두 접근법을 통합하는 방향—SmartNIC/DPU에 Istio 데이터 플레인과
  OPA 정책 평가를 오프로드하여 ZTA의 보안 수준을 유지하면서 성능 오버헤드를 줄이는
  연구—에 관심을 갖고 있으며, 교수님 연구실과의 협력 가능성을 논의드리고 싶습니다.

  [영어 버전]
  ─────────────────────────────────────────────────────────────────────────
  My recent research focused on implementing and experimentally validating a
  Zero Trust Architecture (ZTA) based on NIST SP 800-207 in a Kubernetes
  environment, using a software stack of Istio, OPA, and Keycloak. I designed
  and verified 18 security scenarios covering JWT forgery/tampering, lateral
  movement defense, context-aware authorization (role + HTTP method + path),
  and device posture gating.

  During this work, I came across the Hyperion paper (IEEE TCC, 2024), which
  offloads the container network data plane—including both network
  virtualization and access control—to SmartNIC hardware, achieving up to
  4.3x throughput improvement and 4x CPU reduction over software-based solutions.

  Both studies share the same underlying motivation: enforcing security policy
  outside the application layer, transparently, at the infrastructure level.
  However, they take complementary approaches. Hyperion optimizes for
  performance via hardware offload, while my work emphasizes the ZTA
  principle of continuous, context-aware verification—combining L7 attributes
  (JWT claims, HTTP context, device posture) into dynamic, code-driven policy
  decisions expressed in Rego.

  I am now particularly interested in bridging these two directions: offloading
  Istio's data plane and OPA's policy evaluation to SmartNICs/DPUs to preserve
  ZTA-level security guarantees while eliminating the software proxy overhead.
  I would greatly appreciate the opportunity to discuss potential collaboration
  with your research group in this area.
